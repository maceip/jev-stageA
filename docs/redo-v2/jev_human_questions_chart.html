Can Small Security Models Stop Prompt Injection — And Is Fine-Tuning Worth It?

Measured on unseen Banking + Slack agent tools (AgentDojo v1.2.2) across 29,157 offline test decisions and live gpt-5.4-mini runs.
Good outcome: Work Completed / Attacks Caught (Higher = Better)
Failure / Cost: Agent Hijacked / False Alarms (Lower = Better)
Q1: How good is a 4B JEV-style model at stopping prompt injections in a live AI agent?
Answer: Against 1-try attacks it stops 92%–98% of hijacks (85/249 -> 2/249 live C1 redact, and 85/249 -> 7/249 on the off-the-shelf replay) — and when fine-tuned (C1) to check outgoing tool calls, 188/249 attacked tasks still finish. Against a 10-try adaptive attacker, the off-the-shelf check at 0.99 is bypassed on 53/100 targets.

Q2: Is it worth fine-tuning an off-the-shelf model — and what makes fine-tuning succeed or fail?
Answer: Yes, when teaching a model a new check — false alarms fall 6.8× on text (36.9% dev untrained -> 5.4% test balanced; different splits) and 3.1× on tool calls (43.1% -> 14.1% at one shared threshold, 0.0561). Skewed data or a frozen backbone does not.
